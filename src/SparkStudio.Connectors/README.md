# SparkStudio connectors

Original C# implementation for the gateway. Targets .NET 10 on Windows and Linux. It uses the official OPC Foundation client, Microsoft database providers, libplctag, S7netplus and Beckhoff ADS libraries. Equipment writes require the gateway's published, reviewed command workflow. SQL writes require the separate explicit `ExecuteAsync` operation.

## Industrial devices

The four industrial drivers and six EtherNet/IP family profiles require `0.2.0-preview.12` or a later compatible release; preview.11 and earlier lack these drivers. Exact artifact/source evidence is recorded separately in [Verification and roadmap](../../docs/architecture/PARITY.md). Authored loopback/native fixtures establish their bounded software contracts, while actual device/firmware acceptance remains separate. See the [implementation guide and setup-required workshop](../../docs/architecture/INDUSTRIAL_DEVICE_CONNECTIONS.md).

`ConnectionDefinition.Device` contains a validated `DeviceSettings` snapshot and saved `DevicePoint` map. Driver IDs are `modbus-tcp`, `ab-eip`, `siemens-s7` and `beckhoff-ads`. `DeviceConfiguration.Drivers` provides names, ports and browse modes; `IDeviceSession` separates driver transports/codecs from the service's bounded pool, polling and gateway authorization. Database operations retain their own query contracts.

`ConnectorService` routes test, browse, read, watch and explicit scalar write calls through those drivers. Modbus, S7, Micro800 and PCCC profiles browse configured maps. ControlLogix/CompactLogix controller/program catalogs and ADS symbol trees provide native browsing; `nodeId=@configured` always browses the saved map without network access. Native symbols must become saved points before reads, tags or commands may reference them. Saved maps have 10,000-point and 768 KiB normalized JSON limits. Saving a map does not enable a write: a point must explicitly permit it and an operator must use a published command with Commands permission.

Modbus uses zero-based `coil:0`, `discreteInput:0`, `holdingRegister:0` and `inputRegister:0` addresses. Boolean points use bits; register points support Int16, UInt16, Int32, UInt32, Int64, Float, Double and bounded ASCII String. Byte swaps and word reversal are explicit. Adjacent/overlapping configured read spans coalesce up to protocol limits; input tables cannot be writable. One acknowledged FC5/6/16 request implements each scalar write, with no automatic resend.

EtherNet/IP selects `ControlLogix`, `CompactLogix`, `Micro800`, `MicroLogix`, `Slc500` or `Plc5` explicitly, using pinned libplctag .NET 1.5.2 / NativeImport 1.0.41 (native core 2.6.0). No family fallback occurs. ControlLogix/CompactLogix support symbolic program scopes, array elements, member paths and native catalogs with a required numeric route. String points are rejected during map validation and before device access: the SDK's default STRING size/capacity cannot qualify the controller's structure schema. Micro800 supports symbolic Boolean/numeric scalars with a blank route and connected messaging, including WORD/DWORD as raw UInt16/UInt32; program scopes, numeric bit selectors, String and native browsing are excluded. Active native type and width checks precede decoding/writes in these symbolic profiles. PCCC ST strings retain the separate bounded file codec below.

MicroLogix, SLC 500 and PLC-5 use direct Ethernet PCCC with a blank route and saved-map browsing. The bounded subset is N/B words (Int16/UInt16), N/B bit 0–15 (Boolean), F elements (Float) and standard ST elements (String capacity 1–82, physical layout 84 bytes). MicroLogix additionally permits L files as Int32/UInt32 when the controller provides them. File numbers are 0–255, elements 0–65535; actual allocation limits remain device-specific. Prefixes are case-insensitive. Dedicated PCCC bit-address writes use native masks; a whole B-word write replaces all its bits. Remote symbolic metadata is unavailable for PCCC, so the driver checks address-derived native file kind and returned width. Test for Micro800/PCCC reads the first saved point and rejects an empty map. DH+ bridges, DF1, I/O/status/timer/counter files, subfields, whole structures and implicit I/O are excluded. SDK auto-sync writes are disabled for every family. The [workshop's family/address matrix](../../docs/architecture/INDUSTRIAL_DEVICE_CONNECTIONS.md#ethernetip-family-setup) links pinned official source evidence and the isolated lab walkthrough.

S7 supports classic addressable CPU profiles with rack/slot configuration and explicit DB, marker, input or output byte/bit maps. Writes target only DB/marker memory. Non-optimized DBs and permitted controller communication are required. Numeric codecs use native big-endian layout, Boolean writes use the bit operation, and STRING capacities/layouts are checked. A write must fit one negotiated PDU.

ADS supports typed symbol access and native catalog browsing. Local/target AMS Net IDs and a controller route back to the gateway are required. The gateway owns a shared, reference-counted router when no router is already listening; an installed router must have the configured local identity and administrator-managed target route. Fresh symbol metadata checks reject type/layout changes before writes, and handles receive bounded cleanup. ADS uses polling in this implementation.

`DevicePoint.DataType` is the engineering/tag type; optional `RawDataType` declares the storage codec and defaults to the same type. Numeric scaling is `engineering = raw * scale + offset`, with inverse write conversion and exact integer/range checks. A raw UInt16 point with engineering Double and scale 0.1 exposes 123 as 12.3 while still reading/writing one register. Integer storage/scaling uses the bounded decimal domain, rejecting underflow, overflow and fractional raw integers. Strings and Booleans require matching raw/engineering types and do not permit scaling. Native drivers reject byte/word swaps. Point IDs and encodings are immutable snapshots for an operation; writes never accept a free address from an operator request.

Industrial operations have a 30-second total budget including pool waits; request deadlines are configured from 100–30,000 ms (default 2,000). The pool serializes operations per connection and has 32 resources. Polling uses 100–60,000 ms intervals without overlapping scans, with bounded reconnect delay and shutdown cancellation. Receipts use gateway UTC timestamps because these polling protocols do not provide source timestamps. Bad data/transport quality is explicit. Device write locking conservatively covers the entire host; use one shared `ContentionDomain` for aliases to the same physical controller.

Logix and Micro800 scalar operations use connected CIP messaging; Logix read-only symbol listing uses unconnected messaging. PCCC retains its direct unconnected transport. These modes are fixed by the implemented family profile.

The pinned libplctag.NET `GetByteArrayAttribute` interprets a positive copied-byte count as an error. Symbolic CIP type validation therefore uses a narrow NativeImport metadata bridge while `Tag` retains I/O and handle ownership. The bridge requires managed assembly version `1.5.2.0` and the expected private wrapper/handle field types, bounds metadata to 2–64 bytes and requires an exact copied length. A mismatch fails the read or rejects the write before dispatch; no guessed type substitutes for unavailable metadata. Dependency upgrades must requalify this SDK coupling and the native fixtures.

Source tests exercise Modbus/S7 loopback transports, family/address and codec validation, cancellation, lost acknowledgement and gateway command authority. They do not establish acceptance against actual Rockwell, TwinCAT or S7 devices. See the [industrial workshop](../../docs/architecture/INDUSTRIAL_DEVICE_CONNECTIONS.md) for setup and the [support plan](../../docs/architecture/INDUSTRIAL_PROTOCOLS.md) for later protocols.

## OPC UA

Set `Type` to `opcua` and `Endpoint` to an `opc.tcp://host:port/path` address. `SecurityMode` defaults to `SignAndEncrypt`; explicit `Sign` and `None` are supported. The client selects a supported modern RSA policy matching that exact mode and never silently downgrades. `None` permits anonymous sessions only. Username/password authentication is available for secured sessions.

`DiscoverEndpointsAsync` returns advertised endpoints, security modes, policy URIs, user token types, and SHA-256 certificate fingerprints. Discovery does not authenticate the server. Compare a fingerprint with the server administrator's independently obtained value before saving it as `ServerCertificateSha256`. The pin must match the certificate actually offered, including when that certificate is already trusted. A connection-specific validator permits only the matching certificate's untrusted-root error; certificate hostname, expiry, and other checks remain active. `TrustServerCertificate` applies only to SQL Server and never disables OPC UA validation.

The service creates its application certificate below `<dataDirectory>/pki/own`. Trust its public certificate on the OPC UA server when required. Without a pin, trust the server certificate using the directory store under `<dataDirectory>/pki/trusted/certs`; rejected peer certificates appear in the rejected store. CA certificates and revocation lists can be installed under the issuers/trusted stores. Restart the gateway after manually changing trust-store files. Retain the entire data directory across container replacements, and restrict access to private keys.

`BadSecurityChecksFailed (0x80130000)` commonly means the server has not trusted the SparkStudio client certificate. Inspect the server's rejected-client list and explicitly trust the SparkStudio public certificate using the server's administration tools. For Kepware this is the OPC UA Configuration Manager's trusted clients/certificates workflow. This is separate from SparkStudio trusting Kepware's server certificate. Also use an endpoint hostname present in the server certificate's subject alternative names; a certificate containing only `DNS:machine-name` does not identify `127.0.0.1`.

Browsing starts at the Objects folder when no node ID is supplied. It follows continuation points and returns up to 10,000 local object/variable references. Reads accept up to 1,000 node IDs and preserve OPC UA quality and source timestamp. Unsupported structured values become strings, byte strings become base64, and nonfinite floating values become strings for valid JSON. If neither source nor server supplies a timestamp, the receive time is used.

Browse, read, and test operations reuse a bounded pool of at most 32 OPC UA sessions. Operations on each connection are serialized. Changing connection settings, credentials, or the certificate pin replaces its session; failed or cancelled operations discard their session so the next operation reconnects. When the pool is full, the least recently used idle session is evicted. Gateway shutdown cancels active work and releases all sessions. The connection test performs a real server-time read, including when it reuses a session. These operations have a 30-second deadline and graceful session close is bounded by two seconds.

`WatchAsync(connection, nodeIds, publishingIntervalMs, onValues, onStatus, cancellationToken)` uses real OPC UA monitored items and a separate secure session, so browsing/testing does not block the tag stream. It reads initial values, creates a subscription, then delivers change notifications. Each call accepts 1–1,000 node IDs and a requested publishing interval of 100–60,000 ms; the server may revise sampling/publishing intervals. Duplicate node IDs are deduplicated. Bad item creation/read quality is returned for the affected node rather than pretending that node is healthy.

Watch callbacks are serialized and must return promptly. `onStatus` receives exactly `Connected`, `Reconnecting`, or `Error`; connection attempts start with `Reconnecting`. `onValues` preserves the value, quality, and source timestamp (server timestamp when the source timestamp is absent). Pending updates coalesce to the latest value per node and monitored-item queues discard old values, so this interface represents current tag state rather than lossless historical capture. Bad keep-alives or a stopped subscription cause complete session/item recreation, with a cancellable 1, 2, 4, 8, then 15-second retry delay. Security/pin validation is identical to other connector operations. A changed configuration requires the caller to cancel the old watch and start a new one. Cancellation completes normally after bounded cleanup; invalid input or a failed consumer callback terminates with an exception. Disposing `ConnectorService` also cancels active watches.

## SQL Server

Set `Type` to `sqlserver`, `Server` to the SQL Server address, and `Database` to its database. Username/password selects SQL authentication. Omitting the username selects operating-system integrated authentication, which requires a correctly configured service account/Kerberos environment. TLS encryption and certificate validation are enabled by default. `TrustServerCertificate = true` is an explicit development/deployment override for SQL TLS validation only.

For read-only connections, use a database principal granted only SELECT on the required tables or views. For explicit named updates, grant only the required INSERT/UPDATE/DELETE table permissions. `ApplicationIntent=ReadOnly` is a routing hint, not a security boundary; updates explicitly select `ReadWrite`. The query guard conservatively accepts one SELECT or WITH…SELECT query and rejects obvious mutations, SELECT INTO, stacked statements, remote data access constructs, and sequence increments. It is a query screen, not a complete T-SQL parser or substitute for database permissions. Quoted identifiers, quoted values, nested comments, CTEs, nested SELECTs, and UNION queries are supported.

Pass values as `QueryParameter` records and use `@name` placeholders. Values are bound through `SqlParameter` and never interpolated. Supported types: string/nvarchar, int, bigint, double/float, decimal, bool/bit, date, datetime2, datetimeoffset, and guid. Null becomes SQL NULL. Use unique result aliases when convenient; duplicate/empty column names receive stable suffixes instead of overwriting values.

Limits are 128 parameters, 65,536 characters of query text, a 10-second connection timeout, a 15-second command timeout, a 30-second total deadline, 1,000 rows, and approximately 16 MiB of returned values. A row/size limit raises an error rather than silently returning partial results. Individual string/binary cells and string parameters are limited to 1 MiB. Narrow queries with TOP and WHERE. SQL errors exposed by this library contain numeric error codes and guidance, without logging query text, credentials, or server error details.

## AnyLog query node

The AnyLog client is not compiled into this library. `DatabaseConnectors` is the host seam: a plugin registers a connection type, validates its settings, tests the endpoint and runs a read query. The shipped plugin is `plugins/anylog/`. It wraps a SELECT as `run client () sql <dbms> format=json and <select>` and posts that command to the query node's REST port. Setup, SQL limits and the SparkStudio upgrade steps are in the [AnyLog connector guide](../../docs/architecture/ANYLOG_CONNECTOR.md).

## Managed SQLite

Set `Type` to `sqlite` and `Database` to a flat filename such as `production.db`. Names have a 1–64 character ASCII alphanumeric/underscore/hyphen stem starting with a letter or digit, followed by `.db`, `.sqlite` or `.sqlite3`. Windows device names, directories, URI filenames, connection strings and terminal whitespace are rejected. Files live exclusively under `<gateway data directory>/databases`; file paths and SQLite journal/WAL/shared-memory sidecars are checked for symbolic links and reparse points. This service-owned directory must not be writable by untrusted local users; these checks do not provide isolation against an administrator changing paths concurrently.

`TestAsync` and queries require an existing database and never create one. `CreateSqliteDatabaseAsync(connection, initializeSampleData, ct)` builds a new database in a unique staging file and atomically moves it into place without overwriting existing files. With `initializeSampleData=true`, it creates a fixed `production_records` table with `id`, `work_order`, `machine`, `quantity`, `status`, `recorded_at` and `version`, plus three synthetic rows. The sample supports queued/running/complete statuses, nonnegative quantity and version-based optimistic updates. With `false`, it creates an empty database; arbitrary schema execution is not exposed. `BrowseSqliteSchemaAsync` returns up to 100 tables and 256 columns per table.

Read queries use SQLite's read-only open mode and a native authorizer. Mutations, schema operations, ATTACH, PRAGMA and extension/file access are denied for query execution. Extensions are disabled and trusted-schema execution is off. Each operation has a separate non-pooled connection and the service limits concurrent SQLite work to four operations. SQLite's ADO.NET async methods do not perform asynchronous I/O, so work runs on the thread pool with a native progress callback for actual cancellation. The 30-second deadline includes waiting for a slot; lock waits stop after approximately one second. Result limits are 1,000 rows and approximately 16 MiB; SQLite's native row/string/blob allocation limit is 1 MiB, applied before reading values into managed memory. Query text, parameters and duplicate-column behavior follow the SQL Server connector. Use SQLite `LIMIT` instead of SQL Server `TOP`. SQLite returns its storage types (integer, real, text, blob, null); dates, GUIDs and decimals bind through the provider's text representation, Booleans through integers.

## Explicit SQL updates

`ExecuteAsync(connection, sql, parameters, ct)` returns `ExecuteResult(RowsAffected, DurationMs)` for SQLite and SQL Server. It accepts one `INSERT … VALUES`, `UPDATE`, or `DELETE`; arbitrary DDL, stored procedure execution, batches, INSERT…SELECT, update CTE prefixes, OUTPUT/RETURNING, and upserts are outside this first slice. Values use the same typed `@name` parameters as reads. SQL Server retains its 15-second command and 30-second total limits. SQLite additionally restricts native write authorizations to ordinary tables in the managed main database. Single SQLite statements are atomic, including constraint failure and interruption; no multi-operation transaction API is exposed. A zero-row update is a valid result, including a stale optimistic version condition. Database triggers may still cause permitted changes within their database, so production SQL permissions and authored statements remain the responsibility of the trusted gateway author.

These methods are low-level connector APIs. The gateway must expose writes only through its validated named update definitions and trusted scripting contract, never by accepting arbitrary operator-supplied SQL. Cancellation of a network SQL operation can have an ambiguous commit outcome; do not blindly retry non-idempotent writes.

## Verification

Run `dotnet run --project src/SparkStudio.Connectors.Tests` from the repository root. The executable tests cover SQL statement guards, CTE mutation rejection, comments/literals, bound parameters, SQL connection-string escaping, duplicate result columns, explicit OPC security modes, and JSON-safe values. These tests need no database or OPC server; live integration verification requires actual endpoints and credentials.

Add `-- --sqlite-integration` for disposable SQLite integration tests, including managed creation, schema discovery, persistence, real typed queries and DML, optimistic conflicts, injection rejection, native cancellation, constraint rollback, value/row limits, lock timeout and a directory junction/symlink escape. The tests create and remove only a uniquely named temporary fixture directory. SQL Server DML is covered by statement/configuration checks; a live SQL Server integration test still requires a test server.

Add `-- --opc-integration` to run a disposable OPC Foundation server on an ephemeral loopback port. This verifies actual changing monitored-item notifications, concurrent read/test access, server-stop detection, reconnect and item recreation, bad-node quality, callback failures, and bounded cancellation. Only this isolated test server is stopped/restarted; installed OPC servers and gateways are untouched. The test uses an explicitly unsecured anonymous loopback endpoint, while real deployment connections retain the secure default. Temporary test certificates are generated in a uniquely named OS temporary directory.
