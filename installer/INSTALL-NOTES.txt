SparkStudio 0.2.0-preview.9 - unsigned Windows preview

Preview.9 adds a unified Actions & Events editor, Python component lifecycle and form-value support, compile-only syntax checking, gateway-to-operator session messages and a gateway shutdown crash fix. Its companion bundle contains 29 portable workshops. It retains self-signed HTTPS setup, encrypted configuration backups, scheduled remote delivery and offline recovery. See this release's installation, network access, scheduled backup and recovery guides. Elevated preview.9 service upgrade, operator-PC certificate trust and remote SMB/FTPS acceptance remain pending.

The offline package includes the gateway, .NET runtime, browser Designer and operator application, and CPython. No separate SDK, Node.js or Python installation is required to run it.

Current-user extraction (/PORTABLE=1 /CURRENTUSER) is the evaluation path verified in prior releases; consult this release's notes for this package's verification results. It extracts application files without registering a service, shortcuts or an uninstaller. Use a separate data directory and an unused loopback port; see the installation guide supplied with the release.

On first launch, create an administrator using security/setup-code.txt in the gateway data directory. There are no default credentials. Projects require explicit publication before operators can open them. Accounts, project grants and gateway resources persist on disk.

For a Windows service installation, open PowerShell with Run as administrator on the gateway computer and run:
Get-Content -LiteralPath "$env:ProgramData\SparkStudio\security\setup-code.txt"
Paste the file's code, not its path, into Gateway setup code. Portable, development and container installations use security/setup-code.txt in their configured data directory. The file is removed after initial setup. Preview.8 retains preview.3's setup instructions and compact Designer version label; the full build remains available in its tooltip.

Normal installation requests elevation and creates a LocalService Windows service with retained data in C:\ProgramData\SparkStudio. Choose Local only (the default) or Network access over HTTPS. Local management remains on 127.0.0.1; network access adds a distinct HTTPS port on 0.0.0.0. Enter the DNS hostname or specific IPv4 address used by operators, then choose Generate a self-signed certificate (no files needed) or Use an existing certificate and private key. A stable LAN address such as 10.20.30.40 works without DNS; use four decimal octets without leading zeros. The generated certificate matches exactly the selected DNS name or IP address and lasts one year. Existing certificates need that exact DNS SAN or iPAddress SAN and a matching unencrypted PEM private key. A numeric DNS SAN or common name is insufficient for IP access.

Browsers will warn until each operator computer trusts the self-signed public certificate, or the issuer of a supplied certificate. After installation, use administrator access on the gateway to read C:\ProgramData\SparkStudio\certificates\deployment\gateway-trust.txt and copy only the adjacent gateway-public.cer to operator computers. Verify its fingerprint and follow the instructions for trusted installation. Never share the private key. Setup protects key files but does not install trust, configure DNS or open firewall rules. 0.0.0.0 is only the bind address; network IPv6 is not supported. Managed upgrades default to Keep existing listener settings and preserve the certificate. To renew a generated certificate, deliberately choose Network access and generation again, then trust the replacement public certificate on each operator computer.

An elevated preview.2 retry after a failed preview.1 installation started successfully as LocalService on one Windows host with retained data. Broader installation, service-account secret encryption and ACL behavior, upgrade recovery and uninstall still require acceptance testing.

Preview.8 retains preview.2's fix for preview.1's erroneous 45-second startup timeout caused by anonymously checking the protected /api/health endpoint. The installer uses a direct-loopback-only /api/ready check for product, startup status, bundled Python and process ID. Health details and gateway diagnostics remain protected. Portable extraction and readiness tests do not establish actual elevated service installation acceptance.

Preview.5 retains the wait for the actual owned gateway process to exit before copying application files. Preview.3 could encounter Access denied for clrjit.dll while the old process was still exiting, even after Windows reported the service stopped, and could require Retry. Preview.4 was held after elevated upgrade preparation failed with Windows error 5 before copying files.

Preview.5 fixes that process-access failure by briefly enabling an existing administrator debug privilege only to acquire a minimal process handle, then restoring the original privilege state. An elevated read-only check against the installed LocalService process verified this fallback and restoration without stopping the service or changing data. A later elevated preview.5 upgrade over the running preview.3 service completed successfully on one Windows host. That earlier result does not establish acceptance of these new network installer choices, remote clients, rollback or uninstall.

After a preview.1 startup timeout, back up C:\ProgramData\SparkStudio and retry this installer in the same program directory. Existing data is retained; do not delete it to retry. Use the installer to start the service, or supply an explicit writable --DataDirectory when starting the executable directly.

Back up the complete data directory before upgrading. Connections use Windows account-specific encryption; configure credentials in the target deployment instead of assuming encrypted development data is portable. The installer refuses to adopt an unrelated service or stop a process occupying its chosen port.

The executable is unsigned. Verify its SHA256 checksum from the release. Do not disable Windows security or organization policy to run it. This is a local evaluation preview, not production acceptance.

Gateway Settings > Recovery creates encrypted configuration backups and can deliver them daily to SMB, FTP or explicit FTPS. Prefer FTPS; ordinary FTP exposes its credentials and commands on the network. Configuration archives exclude live databases, history and audit data. Use the offline full-backup procedure when the complete stopped gateway data directory is needed. External databases need separate backups.

Seven-day retention is the default. Uploads are read back and SHA-256 verified before final rename; only then are expired archives with this gateway's exact generated filename pruned. Failed transfers leave earlier remote backups alone. Incomplete retention after successful delivery is reported as a warning. Native Windows UNC calls can outlast their deadline; the gateway retains one bounded worker until Windows returns.

Local-file and loopback FTP transfer/retention/corruption/cancellation checks and untrusted-FTPS rejection have been tested. Actual domain SMB under the service account or supplied credentials and a trusted external FTPS server have not. Restored directories start in quarantine for local review; Windows-protected credentials may require their original machine/account or reentry.
